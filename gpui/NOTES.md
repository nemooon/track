# GPUI 版 所感メモ（2026-11-12）

カレンダーとレポートを GPUI で作り直した結果のまとめ。**数字の事実**と**解釈（Claude の見立て）**を分けて書く。
前半が `gpui-native` ブランチでの作り直し（サーバーなし・CLI 同梱）、後半が最初の試作（Bun API に HTTP でつなぐ版）の記録。

スクリーンショットは実際のクライアント名・作業内容が写るため、リポジトリには含めていない。

## ネイティブ版で作りを変えたこと

- **サーバーをなくした**: アプリと `track-cli` が共通の `track-core` で SQLite（`~/.track/track.db`）を直接読み書きする。Bun・Hono・Prisma は不要
- **AI からのアクセス（A 案）**: Codex スキル／Claude Code コマンドは `runtime.json` の `cliPath` で CLI を見つけ、CLI が DB に直接書く。**アプリを起動していなくても登録できる**
- **CLI の互換**: サブコマンド・フラグ・JSON・エラーコードは `src/cli/index.ts` と同じ。AI 登録の重複防止に使うハッシュも Bun サーバーと同じ値になる
- **外部変更の反映**: SSE の代わりに `PRAGMA data_version` を 1 秒ごとに確認し、CLI や AI が書いたら画面を読み直す
- **AI 生成**: Codex CLI・カスタムコマンド・Apple Intelligence ヘルパーをアプリから直接起動する（プロンプトはサーバーと同じ文面）
- **レポートの見やすさ**: 時間を 10 進数（1.5h）で表示（1h 30m に切替可）。週表示に「週の合計をコピー」（`プロジェクト名<TAB>時間` の行、画面のグループ分けや絞り込みに追従）
- **AI 連携のインストール**: メニューから Codex / Claude Code / 両方を選んで入れる。開発中は `track-dev` の別名で入り、本物の `track` スキルは触らない

## 設定画面（2026-11-12 追加）

- Tauri 版の設定（メモを除く）を別ウインドウとして移した。規則（入力チェック・削除条件・`config.json` の正規化・バックアップ）は track-core に移植し、Tauri 版のサーバーと同じ値を保存する
- 自動バックアップと復元をアプリが持つ（サーバーの役目だったもの）
- 確認: GPUI 版が保存した `config.json` と勤務設定・出力フォーマット（12 列の実フォーマット）を、Bun サーバーの `/api/config`・`/api/settings` がそのまま読めた（コピー DB）
- テスト: 設定まわりの UI テスト 23 件、core 側の追加 37 件（クライアント等の更新・削除、設定保存、config.json、バックアップ・復元、AI の状態とモデル候補）
- Tauri 版との違い: 追加・編集・削除確認はモーダルでなくインライン。勤務時刻は −/+ の 30 分刻み。編集アイコンは歯車（同梱アイコンに鉛筆が無い）

## AI からの編集と取り消し（2026-11-12 追加）

- `track-cli` に工数の検索・一括変更・削除、クライアント／プロジェクト／タグの作成・変更、`history`・`undo` を足した。書き込みは 1 コマンド = 1 トランザクション = 1 操作として `AiOperation` に変更前後の行を残す
- 確認ルールは CLI が強制する（10 件以上の変更、削除、クライアント・プロジェクトの作成、タグの削除は `--confirmed` 必須）
- アプリは外部変更を検知したとき新しい操作を「AI が N 件変更しました［元に戻す］」で出す。起動前の操作は出さない。CLI で取り消された操作は消える
- 確認: コピー DB で `search` → `update`（1 件）→ アプリにバナーとタイトル変更が出る → `undo` で戻る、を通した
- 気づいたこと: GPUI は隠れているウインドウを描き直さない。CLI の変更はウインドウを前に出したときに反映される（状態は裏で更新済み）
- スキルの文面: 共有の `integrations/` は Tauri 版 CLI に無いコマンドを書くことになるので変えず、インストール時に GPUI 版だけ節を足す

## 見た目のブラッシュアップ（Zed 風、2026-11-14）

- 色は `ui/theme.rs` の `Palette`（背景・面・境界線・文字・控えめな文字・強調など意味の名前）から引く。生の色関数は削除済みで、暗い配色は値の組を 1 つ足せば切り替わる。いまは明るい配色に固定（macOS が暗くても明るい）
- ヘッダーは明るいタイトルバー（タブと設定だけ）。日付の移動は各画面のツールバーのまま
- 下に共通の状態バー。カレンダーは表示中の合計と選択中の工数、レポートは行数。AI の［元に戻す］は黄色い帯から状態バーへ移した
- カレンダーの工数は淡い色の面（左の色線と影はやめた）。今日は日付の丸を強調色で塗る
- レポートはドーナツ・凡例・折りたたみをやめ、明細表を全幅にして一番上の行に割合バーを添える（凡例と明細の重なりの解消）。期間の合計は表の合計行だけに出す
- 数字（時刻・時間・割合）は等幅（Menlo）
- 確認: コピー DB でカレンダー・レポート・設定をウインドウだけ撮影して確認

## ネイティブ版の解釈（Claude の見立て）

- サーバーをなくしたことで、Tauri 版で起きていた「同梱サーバーの待機 CPU」「再起動時にサーバーが残る」類の問題がそもそも起きない。メモリはサーバー込みで Tauri 版の約 3 分の 1
- AI からの登録はアプリの起動状態に左右されなくなった。スキルの文面はほぼそのままで動く
- 一方で、DB の構造（マイグレーション）を Prisma 側と Rust 側の両方で守る必要がある。両方を並行して使う期間に Tauri 版が新しいマイグレーションを当てると、Rust 側は知らない構造として書き込みを拒否する（読み取りは続く）

### 再現していない／差がある点

- ドーナツはやめた（Zed 風のブラッシュアップで明細表の割合バーに置き換え）
- 明細表の最小幅 760px と横スクロールがない（狭いウインドウでは列が詰まる）

- ボタンのツールチップ（`title` 属性相当）は付けていない
- タッチ操作・KING OF TIME/Outlook モックは対象外（設計どおり）

## 作ってみての所感（解釈）

**作りやすかった点**
- Tailwind に近いメソッドチェーン（`.flex().gap_2().px_3()`）で、React 版のクラス名をほぼそのまま写せた。見た目の再現は思ったより速い
- `canvas` での自前描画（斜線、破線、ドーナツ）が素直に書ける
- 純粋なロジック（重なり配置、集計、コピー文字列、プロンプト）は Rust に移しても TypeScript のテストをそのまま写して検証できた
- 画面を出さずにクリック・キー入力を流すテスト（`TestAppContext`）が強力。ドラッグ、ダイアログ、日本語変換中の Enter まで自動テストにできた

**苦労した点**
- ドキュメントが薄い。API はほぼ部品ライブラリと Zed のソースを読んで調べた。crates.io の `gpui` は1年前の版で使えず、第三者のスナップショット（`gpui-pre`）に依存している
- Rust 1.97 ではビルドできず、1.98 に上げる必要があった
- `anchored()` のポップオーバーは置き方を誤ると画面上端に出る（テストで発見して修正）
- z-index がなく、重なり順は子要素の順番で決まる
- 部品ライブラリのダイアログは開いた瞬間にフォーカスを奪うので、入力欄へのフォーカスは自前で戻す必要がある
- HTTP は GPUI の実行器とは別に tokio を立てる必要がある
- 自動テストで本物の不具合が3件見つかった（楽観的更新が巻き戻らない、選択中ブロックの高さが縮む、ポップオーバーの位置ずれ）。逆に言えば、目視だけだと見落としやすい
- 最終レビューでさらに、ドラッグ中に期間を移動すると別の日に保存されうる点、起動後のエラーが空表示になる点が見つかり、修正した
