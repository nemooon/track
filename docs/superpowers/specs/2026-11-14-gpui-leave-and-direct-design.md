# 休暇と直行直帰（GPUI 版）設計

## 目的と背景

工数の記録に「その日は働いていない（休暇）」「客先などへ直行直帰した」を残せるようにする。どちらも
1 日の稼働予定時間として数える。将来は勤怠管理の API から自動で取り込む前提（今回は連携しない）。

## 決まったこと（ユーザーの決定）

- **休暇の時間**: 1 日の稼働予定時間。設定の勤務時間（例 10:00〜18:30 = 8h30m）から休憩 1 時間を引く（= 7h30m）。
- **半休**: 前半・後半があり、時間は全日の半分（7h30m → 3h45m）。
- **祝日**: 自動で休暇（全日）扱い。
- **設定のしかた**: カレンダーの日付の見出しのボタンから、休暇（全日・前半・後半）を選ぶ。
- **直行直帰**: 何らかのプロジェクトに紐づく特別なエントリー。時間は休暇の全日と同じ考え方（1 日の稼働予定）。半日はない。
- **直行直帰と普通のエントリーが同じ日にある**: 足し合わせる（例 7h30m ＋ 30m = 8h）。
- **レポート**: 「休暇を含める」の切り替え。オンのとき明細に「休暇」の行が 1 つ増え、合計・割合・草グラフにも入る。
- **作り方（方式 B）**: 直行直帰は普通のエントリーに「直行直帰」の印を付けて保存する。休暇は作業時間ではないので別の表に保存し、祝日はその場で計算して加える。
- 勤怠 API 連携は今回の範囲外。
- **休暇と直行直帰は同じ日に両方持てない（後から選んだ方だけ残す）**: 直行直帰を作るとその日の休暇を消す（祝日なら `none` を保存して自動休暇を打ち消す）。休暇（全日・前半・後半）を選ぶとその日の直行直帰を消す。二重に数えない。

## 方式（検討したもの）

| 方式 | 内容 | 採否 |
|---|---|---|
| A | 休暇も直行直帰も新しい「日の印」の表に入れる | 不採用。直行直帰はプロジェクトの作業時間なので、集計・出力・週報・AI・CLI それぞれに「日の印」を数える処理が要り、漏れやすい |
| **B** | 直行直帰はエントリーに印、休暇は別の表＋祝日の計算 | **採用**。直行直帰は既存の集計にそのまま乗る。休暇だけ切り替えで足す |
| C | 休暇を仮のプロジェクトのエントリーにする | 不採用。プロジェクトの一覧・割合に混ざり、含める／含めないが作りにくい |

## データ

移行ファイル `database/migrations/0017_leave_and_direct.sql`（Tauri 版と共有。Tauri 版の DB にも同じ変更が入るが、既存のデータは変わらない）:

- `TimeEntry` に列 `kind TEXT NOT NULL DEFAULT 'normal'` を足す。値は `normal` か `direct`（直行直帰）。
- 表 `Leave` を作る: `id`（cuid）、`date`（ローカルの日付 `YYYY-MM-DD`、一意）、`kind`（`full`・`am`・`pm`・`none`）、`createdAt`、`updatedAt`。
  - `none` は「この日は休暇にしない」。祝日に働いた日の自動休暇を打ち消すためだけに使う。
- `database/schema.prisma` にも同じ列と表を書き足す（Tauri 版のビルドが schema と食い違わないように）。

track-core:

- `TimeEntry` に `kind: EntryKind`（`Normal` / `Direct`）。既存の読み書き・AI 操作の記録・バックアップと復元で落ちないこと。
- `Leave { date: NaiveDate, kind: LeaveKind }`、`LeaveKind = Full | Am | Pm | None`。
- 祝日の一覧（今は `track-app/src/core/holidays.rs`）を track-core に移し、アプリはそれを使う。

## 時間の計算（track-core）

- 稼働予定 `scheduled_minutes(settings) = max(0, work_end − work_start − 60)`。休憩 60 分は固定（設定は増やさない）。
- ある日の休暇の分 `leave_minutes(day)`:
  - `Leave` に行があればその種類で決める: `full` = 稼働予定、`am`・`pm` = 稼働予定 ÷ 2（分は切り捨て）、`none` = 0。
  - 行がなく、その日が勤務日（設定の勤務曜日）かつ祝日なら、稼働予定（全日）。
  - それ以外は 0。
- 稼働予定は「今の設定」で計算する（過去の休暇も、設定を変えると時間が変わる）。

## 直行直帰（エントリー）

- その日の勤務開始〜勤務終了・休憩 60 分・`kind = direct`・選んだプロジェクト・タイトル「直行直帰」で作る。時間は作った時点の設定で決まり、あとで設定を変えても変わらない。
- 1 日に 1 件まで。同じ日に作り直すと、前のものを置き換える（プロジェクトの変更もこれで行う）。
- 集計（レポート・週報・出力フォーマット・草グラフ・カレンダーの合計）は普通のエントリーとして数える。追加の処理は要らない。

## カレンダー

- **日付の見出し**に小さなボタン（アイコン、ツールチップ「休暇・直行直帰」）を置く。押すとポップオーバーが開く:
  - 休暇: 全日 ／ 前半 ／ 後半 ／ なし。祝日では「なし」が「休暇にしない」になる。選ぶとすぐ保存し、閉じる。
  - 直行直帰: プロジェクトを選ぶと作る（置き換える）。ある日は「直行直帰を外す」で消す。
- 見出しの表示: 休暇なら「休暇」「前半休」「後半休」の印、直行直帰なら「直行直帰 プロジェクト名」の印。祝日の自動休暇は、祝日名の印のままでよい（休暇扱いであることはツールチップで示す）。
- **直行直帰のエントリーは時間の枠に置かない**（見出しの印だけ）。日の合計と下の帯の合計には含める。
- **休暇は日の合計に含めない**。

## レポート

- ツールバーに「休暇を含める」の切り替え。状態は保存する（persist）。初期値はオフ。
- オンのとき:
  - 明細に「休暇」の行を足す（キー `__leave__`）。期間内の休暇の分の合計。合計と割合に入る。
  - 草グラフの日ごとの分に、その日の休暇の分を足す。
- 絞り込み（クライアント・プロジェクト・タグ）がどれか効いているときは、休暇の行は出さず、草グラフにも足さない。休暇はどのプロジェクトにも属さないため。
- 週報・出力フォーマット・週の合計をコピー: 今回は休暇を含めない（直行直帰はエントリーなので含まれる）。

## 範囲外

- 勤怠管理 API との連携。
- 休憩時間の設定。
- 週報・出力フォーマットへの休暇の反映。
- Tauri 版の画面での直行直帰・休暇の表示（Tauri 版では直行直帰は普通のエントリーに見える）。

## 設計者の判断（レビューで出た点）

- **「なし」の保存**: 祝日の日に「なし」を選んだときだけ `none` を保存する。祝日以外の日に「なし」を選んだら `Leave` の行を消す。
- **直行直帰の守り方**: 「1 日 1 件・置き換え」は track-core の作成処理（直行直帰を作る関数）で守る。それ以外の経路（AI 操作・CLI の編集）で時刻やタイトルを変えるのは禁止しない。変えても `kind = direct` のまま、その時間で数える。カレンダーでは時間の枠に出ないので、ドラッグや枠からの編集はできない。
- **バックアップと復元**: バックアップは DB 全体のスナップショット（`VACUUM INTO`）なので `Leave` も入る。復元後は移行を流すので、古いバックアップにも列と表が足される。追加の作業はない。
- **勤務時間が未設定**: 設定の `work_start`・`work_end` は常に値がある（既定 10:00〜18:30）。未設定の場合は考えない。
- **日付の基準**: 休暇の日付はローカル日付。レポートの期間（ローカルの 0 時区切り）と同じ基準で数える。
- **勤務日でない日の休暇**: 手動で付けた休暇は、勤務曜日でなくても稼働予定ぶん数える（自動の祝日休暇だけが勤務日に限られる）。

## 実装する人に任せること

- ポップオーバーの細かい見た目（設定画面の確認ポップオーバー `settings/popover.rs` に揃える）。
- アイコンの種類、印の色（既存のパレットから）。
- 「休暇」の行を開けるか（開けるなら日付と種類の一覧）。
- CLI（track-cli）での `kind` の表示。最低限、既存のコマンドが壊れないこと。
