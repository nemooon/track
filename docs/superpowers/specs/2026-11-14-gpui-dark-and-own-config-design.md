# GPUI 版 暗い配色と専用の設定ファイル 設計

日付: 2026-11-14 / ブランチ: `gpui-native`（未マージのまま続ける）

## 目的と理由

Zed 風の見た目で作った意味の色の層（`Palette`）に暗い配色を足し、明るい・暗いの両方を持つ（前回の決定「両方持つ、まず明るい配色から」の続き）。あわせて、GPUI 版の設定を Tauri 版と共有しない専用ファイルに移す。

利用者の言葉:
- 暗い配色も作ろう
- 切り替えは **設定画面に「自動／明るい／暗い」を置く**（macOS に合わせるだけ、ではなく）
- **共有しない config.json が欲しい**
- AI やバックアップの設定も **専用ファイルへ移す**（Tauri 版と完全に分ける）

## 決まったこと

### 専用の設定ファイル
- データフォルダ（開発中は `~/.track-gpui`、本採用後は `~/.track`）に GPUI 版専用の `gpui-config.json` を置く。GPUI 版の設定（AI・バックアップ・外観）はすべてここに読み書きする
- 共有の `config.json` は GPUI 版からは書かない（Tauri 版の設定はそのまま残る）
- 画面の状態（ズーム・レポートの展開など、`gpui-prototype.json`）は「設定」ではないので別のまま

### 外観
- 設定画面の「ビュー」の先頭に「外観」を足し、**自動／明るい／暗い**を選ぶ。既定は自動
- 自動は macOS の外観に従い、起動中に macOS 側を切り替えてもその場で追従する
- 選ぶとすべてのウインドウ（メイン・設定）が即座に切り替わる
- 暗い値は Zed の One Dark に寄せる。部品ライブラリ（gpui-component の入力欄・ダイアログなど）も同じ明暗に合わせる

### 検討した保存先
- **採用**: 専用の `gpui-config.json` に、外観・AI・バックアップをまとめる（利用者の選択）
- 画面の状態ファイル（`gpui-prototype.json`）に外観だけ入れる案: 設定と状態が混ざるため不採用
- 共有の `config.json` に外観を足す案: Tauri 版と共有するファイルを汚すため不採用

## Claude の判断
- **移行**: `gpui-config.json` が無いときは、初回の読み込みで `config.json` の値（AI・バックアップ）を写して `gpui-config.json` を作る。以後は `config.json` を読まない。写したあとに Tauri 版で変えた値は GPUI 版に反映されない（利用者の理解どおり）
- 入力チェック・既定値・開発用ガード（バックアップ先を `~/.track-gpui` 内に限る）は今の `config.json` の扱いをそのまま使う
- `gpui/scripts/prepare-db.sh` は今までどおり `config.json` をコピーする（初回起動時に `gpui-config.json` へ写される）
- `prepare-db.sh --force`（コピー DB の作り直し）は `gpui-config.json` も消す。次の起動で、写し直した `config.json` から改めて移行される
- 移行で写すバックアップ先が開発用ガードの外（`~/.track-gpui` の外）なら、写さずに既定（データフォルダの `exports`）にする。開発中に本物のバックアップの場所を設定画面に出さないため
- 開発用の環境変数 `TRACK_GPUI_APPEARANCE=light|dark` で外観を一時的に上書きできるようにする（macOS の設定を変えずに撮影で確かめるため）
- 暗い配色でも、プロジェクト色の淡い面（工数ブロック）は背景色と混ぜて作るので、そのまま暗い面になる

## 対象外
- Tauri 版の設定・見た目
- 外観以外の新しい設定項目

## やってはいけないこと
- 共有の `config.json` を GPUI 版が書き換えること
- 移行で AI・バックアップの値を失うこと
- 本物の `~/.track` に触れること（いままでどおりコピー DB で確認）

## 実装者に任せること
- 暗い配色の具体的な値（コントラストは明るい配色と同じ基準を満たすこと）
- 外観の切り替え部品の見た目（3 つのボタンの並びでよい）
- gpui-component の Theme への写し方
