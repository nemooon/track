# GPUI 版 設定画面 設計

日付: 2026-11-12 / ブランチ: `gpui-native`（未マージのまま続ける）

## 目的と理由

GPUI 版（`gpui/`）を、Tauri 版を開かなくても日常運用できる状態に近づける。これまでに作ったのはカレンダー・レポート・AI 連携（CLI）なので、残る大物の「設定」を移す。

利用者の使い方:
- 一番触るのはプロジェクトの追加。流れは「クライアントを作る → その下にプロジェクトを足す → 色を選ぶ」。タグは付けていない。終わった案件のプロジェクトはそのまま残している（アーカイブしていない）
- 出力フォーマットは、新しい案件の報告書に合わせて**必要なときに足す**。頻度は低いが月末に無いと困る
- 勤務時間・週報テンプレート・AI 設定・バックアップは、一度設定したらほぼ触らない
- 復元したことはないが、**自動バックアップは欲しい**
- 重要度は全部平均的。どれかを省けるわけではない

## 方針

**Tauri 版の設定画面をほぼそのまま移す**（利用者:「あんまり変えなくていい」）。項目・文言・入力の制約・保存の挙動は Tauri 版（`src/client/pages/SettingsPage.tsx`、`ProjectsPage.tsx`、`ReportCopyFormatPage.tsx`、`components/SettingsLayout.tsx`）と、その裏のサーバー処理（`src/server/routes/{settings,config,clients,projects,tags,data}.ts`、`src/server/db/backup.ts`、`src/server/config.ts`、`src/server/ai/models.ts`）を正とする。GPUI の部品に合わせた見た目の差は許容する。

## 決まったこと

### 置き方
- 設定は**専用の別ウインドウ**で開く（利用者が選んだ案 C）。左に項目一覧、右に内容。メイン画面を開いたまま使える
- 開き方: `⌘,`、メニュー「Track → 設定…」、**画面内のボタン**（ヘッダー右側。Windows 版も視野に入れるため、macOS のメニューだけに頼らない）
- 既に開いていれば前面に出す（2 つ目を開かない）
- 上タブ型（macOS の旧来の環境設定風）は採らない。Windows 版を考えると不自然なため（利用者の判断）

### 項目（左の一覧の順）
1. **カレンダー**: 勤務時間（開始・終了）、勤務日
2. **レポート**: 出力フォーマット（一覧・追加・編集・並べ替え・削除。編集は `ReportCopyFormatPage` 相当の画面を設定ウインドウ内で開く）、週報テンプレート
3. **プロジェクト**: クライアント・プロジェクト・タグの追加・名前変更・色・アーカイブ・削除（`ProjectsPage` 相当）
4. **AI**: 生成プロバイダー（Apple Intelligence / Codex / カスタムコマンド）、Codex のモデル候補と実行ファイル、カスタムコマンドの実行ファイルと引数、状態表示
5. **バックアップと復元**: 保存先フォルダ（候補として iCloud Drive を出す。フォルダ選択ダイアログ）、実行間隔、保存数、「今すぐバックアップ」、復元ポイント一覧と復元

**メモは作らない**（利用者の判断）。Tauri 版の「ビュー → メモ」項目は無し。

### 保存先と反映
- 勤務時間・勤務日・週報テンプレート・出力フォーマットは DB の `Settings`、AI とバックアップは `config.json`（Tauri 版と同じ場所・同じキー）。Tauri 版とファイルを共有しても互いに読める形式で書く
- 保存したら、開いているメイン画面へ**すぐ反映**する（勤務時間の網掛け、プロジェクトの候補、レポートの出力フォーマット）。同じ接続からの書き込みは `PRAGMA data_version` が変わらないので、外部変更の検知に頼らず明示的に読み直す

### 自動バックアップ
- Tauri 版の同梱サーバーがやっていた仕組みを GPUI アプリに移す: 起動時と 1 時間ごとに「最新の自動バックアップから `backupIntervalHours` 経ったか」を見て、`VACUUM INTO` で `track-auto-YYYYMMDD-HHMMSS.db` を保存先へ書き、自動分を `backupKeep` 本に間引く（手動分 `track-backup-*` は消さない）。間隔 0 は無効
- 復元は `backup.ts` の `restore` と同じ手順: 対象を検証（整合性・必須テーブル）→ 現在の DB を手動バックアップとして退避 → 差し替え → マイグレーション → 開き直し。復元後は画面全体を読み直す
- アプリが動いていないときは取られない（Tauri 版と同じ）。CLI はバックアップを取らない

### 開発中の安全
- 既存の開発用ガードを守る。DB は `~/.track-gpui` 以外を開かない
- **開発版では、バックアップの保存先・復元元を `~/.track-gpui` 配下に限る**（それ以外は保存時に拒否し、iCloud Drive の候補も出さない）。本物の Tauri 版のバックアップは `~/Library/Mobile Documents/com~apple~CloudDocs/Track` にあり、開発版がそこを選ぶと自動分の間引きで本物を消しうるため（Claude の判断）。ガードを外すときに一緒に外す
- `TRACK_EXPORT_DIR` 環境変数は GPUI 版では見ない（Bun 版の開発用上書き。GPUI 版は `config.json` だけを正とする）

## 実装の前提（既存コードの確認結果と Claude の判断）
- **サーバー側の規則は track-core に移植する**。いまの `repo/refs.rs` にあるのは一覧と作成（`create_client` など）だけなので、名前変更・色・アーカイブ・削除と、各ルートの入力チェック（`src/server/routes/*.ts` と `src/shared/validators.ts` の zod）を Rust で書く。削除の規則もルートどおり: プロジェクトは工数があれば `project_has_entries` で拒否、クライアントとタグは DB の外部キー（cascade / set null）に従う
- **`config.json` の読み書き**: 読み込み時の正規化は `loadConfig` と同じ（trim、`backupKeep >= 1`、`backupIntervalHours >= 0`、不正なプロバイダーは既定値）。保存時は**知らないキーを残す**（読み込んだ JSON に上書きして書く）。Tauri 版と同時に動いたときは後に保存したほうが勝ってよい
- **復元**: `DataClient` の DB スレッドは `&mut Db` を持つジョブを実行するので、差し替え後の開き直しもそのジョブ内で行える。必須テーブル（Client・Project・TimeEntry・Tag と、Settings か古い User）と整合性チェックは `backup.ts` のまま移す。マイグレーションは既存の `track-core::migrate`（`database/migrations` を埋め込み済み）を使う
- **AI の状態表示とモデル候補**: `/api/ai/status` 相当（各プロバイダーの利用可否と説明）と、`src/server/ai/models.ts` のモデル候補取得（codex から取得 → ローカルのキャッシュ）を track-core に移す
- **別ウインドウとフォルダ選択**: GPUI の複数ウインドウと `prompt_for_paths` を使う。今回は macOS で作って確かめ、Windows では確かめない。ただし macOS 専用の API には頼らない

## 対象外
- メモ
- AI からプロジェクトを作る機能（別の機会に検討。利用者の判断）
- JSON によるデータ移行（Tauri 版の「データの移行」ダイアログ）・アップデート確認・リリースノート。設定画面の外の機能なので今回は作らない（Claude の判断）
- 設定画面の見た目の作り込み・改善提案（利用者:「あんまり変えなくていい」）

## やってはいけないこと
- Tauri 版の `config.json` や `Settings` の既存の値を、GPUI 版が知らない形式で上書きして Tauri 版で読めなくすること
- 開発中に本物の `~/.track` 配下（DB・バックアップ）を読み書きすること
- 復元で、退避に失敗したまま現在の DB を置き換えること

## 実装者に任せること
- GPUI での部品構成（フォーム部品、色選択、並べ替えの操作方法）。Tauri 版と同じことができればよい
- 設定ウインドウの大きさ・最小サイズ
- 出力フォーマット編集画面を、設定ウインドウ内の画面遷移にするかダイアログにするか
- 自動バックアップを走らせるスレッドの構成（既存の DB スレッド `DataClient` を使う前提で、復元時の DB の開き直しも DB スレッド側で行う）
